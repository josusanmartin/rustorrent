# Rustorrent 0.2 Release Candidate 1

The first release candidate for 0.2. It focuses on uploading: Rustorrent now works harder to let other peers connect to you, and tells you plainly when they can't. It also adds a menu bar mode on macOS and a new icon.

- **Linux x86_64:** `rustorrent-0.2.0-rc.1-linux-x86_64.tar.gz` (needs OpenSSL 3)
- ZIP archives of the app and `SHA256SUMS.txt` are attached below. The app requires macOS 11 or newer.

The app is ad-hoc signed for integrity. It is **not Developer ID signed or Apple notarized**, so on first launch macOS may ask you to allow it: right-click the app, choose **Open**, or allow it in **System Settings › Privacy & Security**.

## Uploading and reachability

A seed only uploads when other peers can connect to it. On many home networks that was failing without any sign.

- **Connectivity in Settings.** A new card, and a line at the bottom of the sidebar, say whether peers can reach you and what to change if they can't:
  - **Reachable:** peers have connected to you.
  - **Port open on your router:** waiting for the first peer.
  - **Incoming port not open:** turn on UPnP or NAT-PMP on the router, or forward the port shown.
  - **Automatic port forwarding is off:** forward the port shown yourself.
  - **Behind a shared internet address:** your provider (carrier-grade NAT) or a second router sits in front of yours.
  - **Blocked by the macOS firewall:** see the next item.
- **macOS firewall.** Rustorrent checks whether the macOS firewall is blocking it. An **Allow incoming connections** button adds it to the allowed list, after the standard administrator password prompt.
- **More routers work.** UPnP now finds newer IGD v2 routers. It falls back to a permanent port mapping when a router refuses timed ones, and reports the router's own error, including "this port is already forwarded to another device".
- **The right port is announced.** When a router opens a different external port through NAT-PMP, trackers and the DHT now announce that port.
- **No more fixed port 6881.** Without `--port`, Rustorrent picks a random incoming port on first run and keeps it. Some providers throttle 6881, and it is often already forwarded to another device.
- **Command line.** `rustorrent remote session` and the terminal interface show the same reachability verdict.

## Menu bar mode on macOS

Closing the window now leaves Rustorrent running as a menu bar icon only, without a Dock icon or app menus. Transfers keep going. Open the window again from the menu bar icon and the Dock icon comes back. You can turn this off in **Preferences** or from the menu bar icon's menu (**Hide Dock Icon When Window Is Closed**).

## New icon

The icon is now an R whose stem ends in a download arrow, inside a cog ring on a rust-orange tile. It is used for the app icon, the window header, the browser tab icon and the README.

## Validation

- **Rust:** 525 unit tests, 9 process tests and 20 transport tests.
- **Real processes:** 8 transfer and crash-recovery scenarios.
- **Transmission interoperability:** a new test in which Rustorrent uploads to a second leecher while it is still downloading. This joins the existing tests for seeding to a leecher on the local network, and for encrypted uploads and downloads.
- **Browser flows** with WCAG A/AA accessibility checks.
- **CI** covers Linux, macOS and Windows, Rust 1.89, dependency advisories and the license notice.
