# Rustorrent 0.2 Release Candidate 8

This release addresses slow downloads with large pieces and many connected peers ([#17](https://github.com/josusanmartin/rustorrent/issues/17)).

## Changes

- Peers can request different blocks of the same piece. With 16 MiB pieces, the per-transfer memory limit still fits four full buffers, but each buffer can now serve multiple peers. Received blocks survive a peer disconnect, and outstanding requests can be picked up by another peer.
- A peer with outstanding requests that sends no data for 15 seconds is disconnected. The Peers view counts a peer as a download source when it has an outstanding request.
- Passing `--preallocate` at startup also applies it to the matching restored torrent.
- Magnet lookups use the current iTorrents HTTPS endpoint. A validated cache hit retains the trackers in the returned torrent file.

The controlled scheduler test covers six peers sharing a 16 MiB buffer and recovering a request after a peer leaves. Throughput on the Linux/NTFS swarm reported in #17 has yet to be measured with this build.

## Download

The macOS app requires macOS 11 or newer. It is ad-hoc signed. ZIP archives and `SHA256SUMS.txt` are also attached.
