# Rustorrent 0.2 Release Candidate 7

The seventh release candidate for 0.2 fixes seeding that stopped uploading after a few hours, and undoes the part of release candidate 6 that made it worse.

![Rustorrent 0.2 RC 7](https://raw.githubusercontent.com/josusanmartin/rustorrent/v0.2.0-rc.7/docs/screenshots/hero-light.png)

## Download

- **Apple silicon:** `Rustorrent-0.2.0-rc.7-arm64.dmg`
- **Intel or Apple silicon:** `Rustorrent-0.2.0-rc.7-universal.dmg`
- **Linux x86_64:** `rustorrent-0.2.0-rc.7-linux-x86_64.tar.gz` (needs OpenSSL 3)
- ZIP archives of the app and `SHA256SUMS.txt` are attached below. The app requires macOS 11 or newer.

The app is ad-hoc signed for integrity. It is **not Developer ID signed or Apple notarized**, so on first launch macOS may ask you to allow it: right-click the app, choose **Open**, or allow it in **System Settings › Privacy & Security**.

## Seeding that keeps finding downloaders

- **New peers are no longer ignored.** Each transfer remembers up to 4,096 peer addresses. Once the list was full, every address learned after that was dropped, so a seed that had run for a few hours never heard of downloaders who joined later. A full list now forgets its oldest address that is not in use.
- **Seeds stay connected to other seeds.** Release candidate 6 closed these connections and announced BEP 21 `upload_only`, as libtorrent does. Seeds pass their peers' addresses on through peer exchange, so that made Rustorrent invisible to the downloaders those seeds were serving. Release candidate 7 keeps the connections and no longer announces `upload_only`.
- **Seeds are not redialled in a loop.** While seeding, a seed that hangs up is dialled again after 10 minutes, not every few seconds as in release candidate 5.

On the Ubuntu 26.04.1 torrent, seeding the same file on the same network for 46 minutes, release candidate 6 uploaded nothing. A build with the address-list fix and release candidate 6's seeding uploaded 243.8 MB, mostly in one burst. This release uploaded 89.0 MB and was the only one that downloaders connected to (14 connections, against none).

Peer exchange keeps the improvements from release candidate 6: connected peers only, at the address that accepts connections, with seed, uTP and encryption flags.

## Validation

- **Rust:** 546 unit tests, 9 process tests and 21 transport tests, on Rust 1.99 and with a compile check on Rust 1.89.
- **Real processes:** 11 transfer, crash-recovery and hole-punching scenarios, including a seed that stays connected to another seed.
- **libtorrent interoperability:** downloads and uploads over uTP.
- **Transmission interoperability:** seeding on the local network, uploading while downloading, and encrypted transfers. The encrypted upload test still fails intermittently on macOS, as in earlier releases.
- **Real swarm:** the Ubuntu 26.04.1 torrent, three seeds side by side.
- **Browser flows** with WCAG A/AA accessibility checks.
- **CI** covers Linux, macOS and Windows, Rust 1.89, dependency advisories and the license notice.
